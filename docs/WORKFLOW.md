# 通用开发工作流（好奇猴快传为首个示范项目）

适用于今后所有新的网页、安卓应用和小工具：**极简、独立、自主维护、先在线体验、边看边改，满意后发布**。不需要每个项目重新搭流程。

AgentDock 中已注册可复用工作流模板：`hamoki-universal-dev-preview-release`（v1.0.5，8 步）。新项目创建时先进行模板匹配，再按项目性质选择对应的预览方式。

- **静态前端项目**：使用 GitHub Pages 自动构建在线预览，改完刷新查看。
- **带后端的网站、工具**：优先复用美国 VPS 的隔离 Docker 开发方式。每个新项目独立 Compose 名、目录、卷、端口和密钥；通常共享 `dev.2858888.xyz/项目名/` 路径，避免重复申请域名；确有安全隔离需求时使用独立子域名。
- **安卓 App**：提供可安装的测试 APK 或等效安全分发；若有网页管理端，可同时使用在线预览。
- **源码流程**：开发期间保存 Git 版本，用户验收后再发布稳定版。是否先公开新项目仓库可依用户要求决定，不能把未完成品当作正式版。

**每次都要给用户可直接打开的测试入口、已验证和未验证项；测试地址没有真正访问成功，就不能宣称完成。**

## 固定工作流

1. 用户提出界面或功能想法；开发者直接进行修改。
2. **前端视觉改动**：提交到 GitHub 后，由 Actions 自动部署到 GitHub Pages 预览站。开发者确认成功后，直接给用户可打开的链接（不以提交成功代替网页可用）。
3. 用户在电脑或手机浏览器中验收，反馈具体体验，开发者根据反馈继续修改。
4. **涉及真实后端的改动**：优先使用已建成的独立测试环境，参见 [完整测试环境记录](STAGING.md)。前后端联调、上传、扫码领取、过期清理、异常处理等在测试站完整验证，不把 GitHub Pages 当成真实传输服务器。
5. 用户明确验收后，生成正式版本、更新项目文档并部署正式站点；发布稳定版需获得用户确认。
6. **正式网址和完整功能已实际验证后，回收该项目的临时测试链接**：撤销 `/项目名/` 的公网反向代理路由（含其静态资源与 API）、从公共首页移除项目卡片、停止并根据保留政策清理专属测试容器和数据。原测试链接必须返回 404 或 410，不自动跳转正式网址；公共开发中心根域名继续运行。

## 独立测试环境原则（已部署独立公网 HTTPS 测试站）

- 统一使用公用 `dev.2858888.xyz` 域名根目录作为开发项目索引，应用按 `/<项目名>/` 分配独立入口；每个项目仍使用独立 Compose、卷、端口和密钥，不修改已经运行的 1Panel、Docker、现有网站端口与容器。
- 测试环境设置资源限制、访问保护和 HTTPS；测试文件定期清理，不使用生产密钥和真实敏感文件。
- 开发分支/临时提交驱动预览；测试通过再更新默认分支及 Release。Git 是版本备份，不建议把「最后再上传 GitHub」作为唯一保存机制。
- **已建立独立的后端测试容器（2026-10-12）**：美国 Raksmart VPS 宿主机 `/opt/hamoki-dev/app`，Compose 项目 `hamoki-dev`，仅绑定 `127.0.0.1:8018`，持久数据 `./data`，密钥仅存在宿主机 `.env`，未提交 Git。
- **验证记录**：容器健康接口正常；测试文字上传、取件查询、SVG 二维码、文字领取、文件上传并校验下载字节，以及未授权上传返回 403 均通过。
- **已完成**：`https://dev.2858888.xyz/` 为共享测试中心首页，`https://dev.2858888.xyz/kauichuan/` 为快传测试入口。Let's Encrypt HTTPS 证书和自动续期已配置；公司电脑实际访问 HTTP 200，公网 HTTPS 上传、取件码、二维码、文件及文字下载测试通过。
- **注意**：快传仍需要私密上传授权；其他新项目复用开发测试中心，但不共用 Hamoki 的密钥、存储或容器。同域名不同子路径不等于浏览器安全隔离：有敏感操作或不可信代码时使用独立子域名。
- **重要**：现阶段测试容器是人工部署的，不是 GitHub 提交自动部署；更新测试环境须先检查改动、备份并确认测试通过。

## 每次交付内容

开发者至少提供：①可直接打开的在线验收链接；②本次变化摘要；③已验证和未验证的项目；④需要用户重点检查的地方。

一切以使用者打开网页、实际体验为准，不以「改完代码」等同于「功能已完成」。

## 测试完成后的下线规则（所有项目通用）

- **测试链接不是永久服务**。例如好奇猴快传使用 `https://dev.2858888.xyz/kauichuan/` 测试，待正式站点部署并由用户确认可用后，该路径及其 API、二维码和下载链接统一返回 HTTP **410 Gone**（无法配置 410 时才使用 404）。
- 公共开发中心 `https://dev.2858888.xyz/` **永久保留**，只保留仍在测试中的项目卡片；下线项目不得继续出现在列表。
- 执行次序：明确验收 → 发布/交付正式版本 → 真实验证正式地址 → 检查测试数据与仍有效的临时分享、说明取件码将失效 → 保留必要恢复备份 → 先下线公网路由并验收 410 → 停止项目容器 → 按项目约定清理临时数据 → 更新项目/恢复文档。
- **除非用户明确说现在结束测试，否则不得提前关闭**。仅提交 GitHub 或产生一个 ZIP/APK，不等于正式站点完成验收。下线默认不删除 GitHub 源码、Release、正式站点和经批准保留的加密/私密备份。
- 如果项目还在开发，即使长时间没有新提交，也不因“闲置”擅自移除。若用户另行约定自动超期清理，应先定义测试租期、数据保留和通知策略。

## 公用域名按需开关（开发站生命周期）

- **永久保留**：`dev.2858888.xyz` 的 DNS、HTTPS 证书及续期配置；不需要每个项目重新配置域名。
- **有待验收的项目**：开启开发测试站，公共首页仅展示当前测试中的项目，项目通过 `/项目名/` 提供临时访问。
- **没有测试项目**：最后一个项目经用户确认正式交付、移除其入口和路由、停用对应容器后，执行 `dev-site.sh sync`。它检测到项目数为 0，会把该测试站切到离线配置，使外界访问返回 Nginx `444`（断开连接，浏览器会显示无法打开）。**不是关闭服务器的 80/443 公共端口，也不是删除 DNS**；其他正式网站保持不变。
- **准备下一个项目**：通过 AgentDock 已授权的宿主机通道执行 `dev-site.sh on` 开启，再部署和登记新项目；无需用户手工操作服务器。
- 这不是按时关闭的定时任务：**在“开始新项目”和“最后项目正式下线”这两个工作流节点触发切换**。目前好奇猴快传仍在测试，不会提前关站。
- 现场的开关脚本为 `/opt/hamoki-dev/dev-control/dev-site.sh`，GitHub 备份：[控制脚本](../ops/shared-dev-site.sh) 与 [离线配置](../ops/shared-dev-offline.conf)。脚本支持 `status`、`on`、`off`、`sync`（按已注册的项目数量决定开关）。检测到还有项目时拒绝强制 `off`，修改 Nginx 前会备份、语法检查，失败恢复旧配置。
- 离线后仍保留 HTTP-01 证书续期验证路径以免证书过期。对外扫描与攻击风险显著降低，但**并不意味着美国 VPS 的其他服务完全免于攻击**。
