# 好奇猴快传 · 开发与在线验收流程

本项目追求：**极简、独立、自主维护、边看边改**。以下流程是默认约定，不需要使用者反复下载源码、安装软件或手工构建才能看效果。

## 固定工作流

1. 用户提出界面或功能想法；开发者直接进行修改。
2. **前端视觉改动**：提交到 GitHub 后，由 Actions 自动部署到 GitHub Pages 预览站。开发者确认成功后，直接给用户可打开的链接（不以提交成功代替网页可用）。
3. 用户在电脑或手机浏览器中验收，反馈具体体验，开发者根据反馈继续修改。
4. **涉及真实后端的改动**：优先使用独立测试环境（待搭建）。前后端联调、上传、扫码领取、过期清理、异常处理等在测试站完整验证，不把 GitHub Pages 当成真实传输服务器。
5. 满足验收标准后，再生成正式版本、更新项目文档和部署正式站点；稳定版发布须明确用户确认，避免影响正在运行的服务。

## 在线入口

- [前端在线预览（GitHub Pages）](https://xiaohouzidoudou.github.io/hamoki-transfer/)
- [当前开源源码](https://github.com/xiaohouzidoudou/hamoki-transfer)
- [前端自动部署工作流](https://github.com/xiaohouzidoudou/hamoki-transfer/actions/workflows/preview-pages.yml)

GitHub Pages **仅用于视觉和静态交互预览**；文件上传、取件等接口不在该站运行。修改后需要等待 GitHub Actions 任务成功；如果部署失败，由开发者检查日志并修复，不要求用户自己排错。

## 独立测试环境原则（待搭建）

- 使用独立 Docker Compose 项目、独立卷、独立域名或子域名；不修改已经运行的 1Panel、Docker、现有网站端口与容器。
- 测试环境设置资源限制、访问保护和 HTTPS；测试文件定期清理，不使用生产密钥和真实敏感文件。
- 开发分支/临时提交驱动预览；测试通过再更新默认分支及 Release。Git 是版本备份，不建议把「最后再上传 GitHub」作为唯一保存机制。
- **当前尚未建立可公开访问的后端测试站点**，不能误称为已完成。

## 每次交付内容

开发者至少提供：①可直接打开的在线验收链接；②本次变化摘要；③已验证和未验证的项目；④需要用户重点检查的地方。

一切以使用者打开网页、实际体验为准，不以「改完代码」等同于「功能已完成」。
