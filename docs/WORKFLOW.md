# 通用开发工作流（好奇猴快传为首个示范项目）

适用于今后所有新的网页、安卓应用和小工具：**极简、独立、自主维护、先在线体验、边看边改，满意后发布**。不需要每个项目重新搭流程。

AgentDock 中已注册可复用工作流模板：`hamoki-universal-dev-preview-release`（v1.0.2，8 步）。新项目创建时先进行模板匹配，再按项目性质选择对应的预览方式。

- **静态前端项目**：使用 GitHub Pages 自动构建在线预览，改完刷新查看。
- **带后端的网站、工具**：优先复用美国 VPS 的隔离 Docker 开发方式。每个新项目独立 Compose 名、目录、卷、端口、测试域名和密钥；上线 HTTPS 后才发公网地址。
- **安卓 App**：提供可安装的测试 APK 或等效安全分发；若有网页管理端，可同时使用在线预览。
- **源码流程**：开发期间保存 Git 版本，用户验收后再发布稳定版。是否先公开新项目仓库可依用户要求决定，不能把未完成品当作正式版。

**每次都要给用户可直接打开的测试入口、已验证和未验证项；测试地址没有真正访问成功，就不能宣称完成。**

## 固定工作流

1. 用户提出界面或功能想法；开发者直接进行修改。
2. **前端视觉改动**：提交到 GitHub 后，由 Actions 自动部署到 GitHub Pages 预览站。开发者确认成功后，直接给用户可打开的链接（不以提交成功代替网页可用）。
3. 用户在电脑或手机浏览器中验收，反馈具体体验，开发者根据反馈继续修改。
4. **涉及真实后端的改动**：优先使用已建成的独立测试环境，参见 [完整测试环境记录](STAGING.md)。前后端联调、上传、扫码领取、过期清理、异常处理等在测试站完整验证，不把 GitHub Pages 当成真实传输服务器。
5. 满足验收标准后，再生成正式版本、更新项目文档和部署正式站点；稳定版发布须明确用户确认，避免影响正在运行的服务。

## 独立测试环境原则（已部署独立公网 HTTPS 测试站）

- 使用独立 Docker Compose 项目、独立卷、独立域名或子域名；不修改已经运行的 1Panel、Docker、现有网站端口与容器。
- 测试环境设置资源限制、访问保护和 HTTPS；测试文件定期清理，不使用生产密钥和真实敏感文件。
- 开发分支/临时提交驱动预览；测试通过再更新默认分支及 Release。Git 是版本备份，不建议把「最后再上传 GitHub」作为唯一保存机制。
- **已建立独立的后端测试容器（2026-10-12）**：美国 Raksmart VPS 宿主机 `/opt/hamoki-dev/app`，Compose 项目 `hamoki-dev`，仅绑定 `127.0.0.1:8018`，持久数据 `./data`，密钥仅存在宿主机 `.env`，未提交 Git。
- **验证记录**：容器健康接口正常；测试文字上传、取件查询、SVG 二维码、文字领取、文件上传并校验下载字节，以及未授权上传返回 403 均通过。
- **已完成**：`https://dev.2858888.xyz/` 已成功接通美国 VPS 独立容器，Let's Encrypt HTTPS 证书和自动续期已配置；公司电脑实际访问 HTTP 200，公网 HTTPS 上传、取件码、二维码、文件及文字下载测试通过。
- **注意**：`dev.2858888.xyz` 真实站需要私密上传授权，公开访问默认仅能查看及领取；其他新项目复用此部署流程而不共用 Hamoki 的密钥、存储或容器。
- **重要**：现阶段测试容器是人工部署的，不是 GitHub 提交自动部署；更新测试环境须先检查改动、备份并确认测试通过。

## 每次交付内容

开发者至少提供：①可直接打开的在线验收链接；②本次变化摘要；③已验证和未验证的项目；④需要用户重点检查的地方。

一切以使用者打开网页、实际体验为准，不以「改完代码」等同于「功能已完成」。
